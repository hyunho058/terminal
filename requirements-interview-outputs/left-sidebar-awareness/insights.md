# Deep Interview Insights: 좌측 사이드바 "상황 인지판"
> Date: 2026-07-21

> Final Ambiguity Score: 0.12 ✅

## Core Problem
좌측 사이드바에 "무엇을 예쁘게 표시할까"가 아니라, "여러 세션 중 지금 당장
내 손이 가야 할 곳을 놓치지 않게" 만드는 것 — 특히 *멈춘 에이전트를 놓칠까 봐
세션을 계속 훑는 폴링 행동*을 없애는 게 진짜 문제다.

## Key Insights & Decisions
- 사이드바의 정체성은 **탭 스위처/런처가 아니라 "상황 인지판"** — 여러 세션의
  상태를 한눈에 파악하는 게 1순위 역할.
- 손을 움직이게 만드는 신호는 **딱 3가지**: ① 에이전트가 내 입력을 기다리며
  멈춤(핵심) ② 오래 걸린 백그라운드 명령 완료 ③ 에러 발생.
- **레이아웃 규칙**: 기본 세션 목록은 **시간순 정렬**, 알림 발생 시 최상단 별도
  **"waiting" 영역**에 표시.
- **해소 모델**: waiting 항목은 사용자가 **클릭/해당 세션으로 이동하면 제거**되는
  *확인(acknowledgement) 기반* — 자동 소멸 아님.
- **v1 범위 (B)**: 에러·백그라운드 완료 감지가 v1의 핵심 가치이므로 **셸 통합
  (OSC 133 / exit-code 캡처)을 v1 범위에 포함**. (에이전트 멈춤은 기존
  `~/.claude/projects/**/*.jsonl` 감시로 이미 가능.)
- **한 행의 표시 우선순위**: 1순위 **신호 종류**, 2순위 **세션 이름**. 경과
  타이머·에러 문구 조각은 좁은 행에서 **버려도 됨**.
- **waiting 내부 정렬**: 신호 종류는 *보여주기만* 하고, 정렬 키는 **기다린 시간순**.
- **"에러" 판정 규칙**: 방금 끝난 명령의 **종료 코드 ≠ 0**, 단 **무시목록
  {1, 130}** 제외(= grep 무매치·Ctrl-C는 안 띄움). 나머지 non-zero만 대기 영역.
- **신선도(지연) 예산**: **멈춘 에이전트는 최대 5초 이내** 대기 영역 등장. 느린
  폴링이 아니라 **파일 이벤트 감시로 "체감 즉시"**. (exit-code/OSC 133은 PTY를
  타고 거의 즉시.)

## Defined Requirements
- **대표 표시 콘텐츠 = 세션별 "주목 필요" 상태 배지**(멈춘 에이전트 / 백그라운드
  완료 / 에러) + 최상단 waiting 영역.
- waiting 행 = `[신호 종류] 세션 이름`, 기다린 시간순 정렬.
- 기본 세션 리스트: 시간순 정렬 유지.
- waiting 항목: 알림 세션 pinned; 클릭/이동 시 제거.
- 감지: 에이전트=jsonl 파일 이벤트 감시(≤5초), 완료/에러=셸 통합 OSC 133/exit-code.
- 에러 = exit code ∉ {0, 1, 130}.

## Identified Risks & Failure Modes
- **감지 신뢰성**: OSC 133/exit-code 셸 통합이 없으면 "완료/에러" 오탐·누락 →
  v1에 셸 통합을 넣어 정면 수용.
- **오탐이 신뢰를 죽인다**: 대기 영역이 무의미한 이유로 켜지면 사용자는 다시 수동
  스캔으로 회귀(= 실패). {1,130} 무시목록으로 1차 방어.
- **알림 폭주(노이즈)**: 세션 8개+에서 동시에 여러 알림 → 인지 부하.
- **신선도 미달**: 멈춘 에이전트가 5초 넘게 안 뜨면 사용자가 못 참고 수동 스캔.

## Open Questions & Unknowns
- **신호 종류의 시각 인코딩**: 1순위로 "신호 종류"를 보이기로 했으나 이를 색/글리프
  /텍스트 라벨 중 무엇으로 구분할지는 미확정.
- **"백그라운드 완료"의 '오래 걸림' 기준**: 몇 초 이상 실행된 명령을 완료 알림으로
  볼지 임계값 미정.
- **알림 폭주 상한**: waiting 영역이 길어질 때 최대 표시 개수/그룹화 여부 미정.

## Success Criteria (측정 가능)
- **멈춘 에이전트 확인용 세션 훑기: 하루 ~20회 → ~3회.**
- 멈춘 에이전트는 발생 후 **≤ 5초** 안에 대기 영역에 등장.
- 실패 판정: 출시 일주일 뒤에도 여전히 ~20회거나 멈춘 에이전트를 여전히 놓침.
