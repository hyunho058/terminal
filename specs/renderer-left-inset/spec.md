# Spec: renderer-left-inset

## Meta

- **Type**: dev

## Goal
Add a `left_inset` to the renderer (mirroring the existing `set_top_inset`) so the terminal grid can be narrowed by a caller-set left band — the reserved column strip the left vertical tab sidebar will paint into. The grid and glyphs shift right by the inset, and `grid_size()` reports fewer columns (rows unchanged).

## Non-goals
- Drawing anything into the reserved left band (the vertical tab sidebar owns that — feature `vertical-tab-sidebar`).
- Calling `set_left_inset` / choosing the sidebar width / re-fitting the grid (the app owns that — feature `tab-click-switch`).
- Removing or renaming `top_inset` — it stays, additive and unremoved (SD1); other layers (cursor, image, current tab bar) still read it.
- Any GUI-crate / widget layout (`no-gui-crates` rule).

## Confirmed Goal
The renderer gains a `left_inset: f32` (physical px reserved to the left of the grid), the exact structural twin of `top_inset`: a `set_left_inset(px)` setter + `left_inset()` getter, a `FrameCtx::left_inset` field for draw layers, the inset threaded into `grid_dims` (so `cols` shrink while `rows` stay full), and both the cell-bg and glyph WGSL shaders shifting `px.x` right by the inset. With `left_inset == 0.0` (the default) every output is byte-for-byte identical to today.

## Research
- `set_top_inset(px)` clamps to `>= 0.0` then calls `write_uniforms()`; a paired `top_inset()` getter returns the value (`crates/renderer/src/lib.rs:477-485`). This is the exact seam to mirror.
- `grid_dims(width, height, cell, top_inset)` is a free function (GPU-free, unit-tested): `cols = floor(width/cell.0).max(1)`, `usable_h = (height - top_inset).max(0)`, `rows = floor(usable_h/cell.1).max(1)` (`crates/renderer/src/lib.rs:985-990`). `cols` currently ignores any inset — left_inset must subtract from width here.
- `grid_size()` calls `grid_dims(config.width, config.height, cell_size, top_inset)` (`crates/renderer/src/lib.rs:461-468`).
- `top_inset` is stored on `Renderer` (`lib.rs:163`), defaulted `0.0` in all three constructors (`lib.rs:302,339,426`), and pushed into both uniform buffers by `write_uniforms()` (`lib.rs:551-572`) and into `FrameCtx` at draw time (`lib.rs:696`).
- `FrameCtx` carries `top_inset: f32` for layers to read (`lib.rs:122`); the tab bar reads `ctx.top_inset` as its band height (`crates/renderer/src/tab_bar.rs:384`).
- Uniform mirrors: `BgUniforms { viewport:[f32;2], cell:[f32;2], top_inset:f32, _pad:[f32;3] }` = 32 bytes; `GlyphUniforms { viewport:[f32;2], top_inset:f32, _pad:f32 }` = 16 bytes (`lib.rs:83-98`). A test asserts these sizes (`lib.rs:1043-1048`) — WGSL uniform blocks must stay 16-byte-aligned multiples and the Rust mirrors must match or the shader reads garbage.
- Shaders map top-left pixel space → clip: `clip.x = px.x / viewport.x * 2 - 1`, `clip.y = 1 - (px.y + top_inset)/viewport.y * 2` in both `cells.wgsl:28-39` and `glyph.wgsl:30-42`. The `+ top_inset` on `y` is exactly where a `+ left_inset` on `x` goes.
- `write_uniforms()` is also called by `resize`/`apply_config`; `set_top_inset` does NOT reset `last_snapshot` — inset changes only the uniform, not the per-cell instance buffers (grid positions are in cell coords), so no re-shape/cache-invalidation is needed (`lib.rs:477-480` vs the `last_snapshot = None` in `resize`/`apply_config`).
- Rules in force: `common ← term-core ← renderer ← app` dependency direction; macOS-only (Metal assumed); no GUI crates; no `unwrap()` outside tests; per-crate `thiserror` errors (`.claude/rules/*`, CLAUDE.md).

### SD1: The reserved tab band moves from a top inset (reserves rows) to a left inset (reserves columns)
- **Status**: resolved
- **Rationale**: The sidebar is vertical on the left, so the grid must shrink in *width*, not height. A `left_inset` (physical px reserved left of the grid) mirrors the existing `top_inset` seam exactly: `grid_dims` subtracts it from usable width so `cols` shrink while `rows` stay full; the bg/glyph shaders shift `px.x` right by `left_inset` just as they shift `px.y` by `top_inset`; `FrameCtx` carries it so the tab layer reads one authoritative value. `top_inset` is kept in the renderer (additive, unremoved) but driven to `0.0` by the app once the sidebar is on the left. Rejected: repurposing/renaming `top_inset` (breaks the additive-seam precedent and the cursor/image layers that already read `top_inset`); a separate width-only code path (duplicates the proven inset arithmetic).

### SD2: Tab-strip geometry is defined ONCE in `tab_bar.rs` as pure functions; the app's click hit-test consumes the SAME functions
- **Status**: resolved
- **Rationale**: Click-to-switch must map a cursor (x, y) to a tab index using the exact geometry the layer draws with. Duplicating the layout math in the app would drift. So `tab_bar.rs` owns the geometry as pure, unit-testable free functions (extending the existing `height_px(cell_h)` precedent), named authoritatively so the consumer imports the right symbols: `width_px(cell_w) -> f32` (the sidebar width the app feeds to `set_left_inset`), `tab_height_px(cell_h) -> f32` (the per-tab slot height / stride), a shared forward `slot_y(index, tab_h) -> f32` the draw path uses to place each slot's top, and its exact inverse `tab_at(x, y, sidebar_w, tab_h, count) -> Option<usize>` the click path uses. Because slots have no top pad or inter-slot gap, `slot_y` (`index*tab_h`) and `tab_at` (`floor(y/tab_h)`) are exact inverses; a round-trip unit test pins their agreement so drawing and hit-testing cannot silently diverge. The app calls `set_left_inset(width_px(cell_w))` and, on a left-button press inside the sidebar, routes through the hit-test → `Tabs::jump(i)`; the SAME `set_left_inset(width_px(..))` wiring runs on the config-reload path so the reserved band never goes stale against the drawn sidebar. Rejected: computing tab bounds independently in the app (two sources of truth, guaranteed drift); exposing only raw slot rectangles (pushes the floor/bounds logic back into the caller, re-opening the drift this closes).

### SD3: Preserve the existing tab architecture and chords; click-to-switch is purely additive
- **Status**: resolved
- **Rationale**: The tab set (`Tabs`), the `TabAction` chord table (Cmd+T/W, Cmd+Shift+[/], Cmd+1..9), the one-way `TabModelHandle` data flow (app writes `TabBarModel`; renderer only reads), the `DrawLayer` registration seam (`add_layer`, z-order), and the enforced dependency direction `common ← term-core ← renderer ← app` all stay intact. The renderer never reaches into `crates/app`; the app never hands the renderer a live `Grid`. Click routing is a new `WindowEvent::MouseInput`/`CursorMoved` handler in the app that reuses the existing `Tabs::jump` + `sync_tab_model` + `redraw` path — no new switching logic. Rejected: adding a widget/GUI crate for hit-testing (violates the `no-gui-crates` rule — draw and hit-test on the cell grid ourselves).

### SD4: Every feature lands green under the project's fixed gates, including the insta suite
- **Status**: resolved
- **Rationale**: Each feature must leave `cargo build`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` (which includes the `term-core` insta snapshot tests) passing, with no `unwrap()` outside tests and per-crate `thiserror` error enums. The vte→grid insta snapshots construct grids at fixed sizes and are not expected to change; if any snapshot output shifts, it is reviewed and accepted via `/insta-review` rather than blindly overwritten. Renderer inset arithmetic stays a unit-testable free function (no GPU needed), matching the `grid_dims`/`height_px` test precedent. Rejected: skipping clippy/tests between features (each spec is independently verifiable and build-order-ready).

### D5: Add `left_inset` as a parallel field/setter/getter — never fold it into `top_inset`
- **Status**: resolved
- **Rationale**: `Renderer` gets a `left_inset: f32` field beside `top_inset`, defaulted `0.0` in every constructor, with `set_left_inset(px)` (clamp `px.max(0.0)`, then `write_uniforms()`) and `left_inset()` getter — a line-for-line twin of `set_top_inset`/`top_inset` (`lib.rs:477-485`). `FrameCtx` gains a `left_inset: f32` field populated at draw time next to `top_inset`. Two independent insets are kept because they are orthogonal geometry axes (one reserves rows, one reserves cols) and both may legitimately be non-zero; conflating them into one value would make a future top-band + left-band impossible and break existing `top_inset` readers. Rejected: a single `Inset { top, left }` struct (churns the existing `top_inset` public API and every call site for no benefit).

### D6: `grid_dims` subtracts `left_inset` from usable width, exactly mirroring the height path
- **Status**: resolved
- **Rationale**: `grid_dims` gains a `left_inset` parameter: `usable_w = (width - left_inset).max(0.0)`, `cols = floor(usable_w / cell.0).max(1.0)` — the symmetric twin of the existing `usable_h`/`rows` computation, keeping the `.max(1)` floor so a pathological inset wider than the window still yields ≥1 col (matching the existing rows-floor guarantee at `lib.rs:988` and its test). `grid_size()` passes `self.left_inset` alongside `self.top_inset`. Staying in the one free function keeps the arithmetic GPU-free and unit-testable (D10/SD4). Rejected: computing col reduction at the call site (splits the inset arithmetic across two places).

### D7: Both shaders add `left_inset` to the uniform block and shift `px.x`; alignment is preserved deliberately
- **Status**: resolved
- **Rationale**: `cells.wgsl` and `glyph.wgsl` each add `left_inset: f32` to their `Uniforms`/`U` struct and change `clip.x` to use `px.x + u.left_inset` (twin of the existing `px.y + u.top_inset`). Byte layout is chosen so both structs stay 16-byte-aligned multiples with Rust mirrors matching: `BgUniforms` becomes `viewport[2] + cell[2] + top_inset + left_inset + _pad[2]` = 32 bytes (unchanged size), with `left_inset` at byte offset 20; `GlyphUniforms` becomes `viewport[2] + top_inset + left_inset` = 16 bytes (the former `_pad:f32` slot at offset 12 is now `left_inset`, size unchanged). **Known risk (the steelman against this decision):** the WGSL↔Rust agreement is *field-order/offset* correctness, and the only automated guard — `uniform_blocks_are_16_byte_aligned` — asserts sizes (32/16) only, not offsets; the bind entry uses `min_binding_size: None`, so pipeline creation validates nothing either. A transposed WGSL field (e.g. `left_inset`/`top_inset` swapped) sums to the same size and silently reads garbage. This is an accepted risk because it is *exactly the existing situation for `top_inset`* (already hand-mirrored the same way) — the mitigation is that both shaders place `left_inset` as the LAST scalar in each struct at the offsets above, and this ordering is called out in the task so the implementer mirrors it deliberately. Rejected: adding a fresh 16-byte row per inset (wastes a uniform slot; the padding already present absorbs the new field).

### D8: `set_left_inset` writes uniforms only — it does NOT invalidate the snapshot cache
- **Status**: resolved
- **Rationale**: Per-cell instance buffers store grid positions in *cell* coordinates; the inset is applied purely in the vertex shader via the uniform. Changing the inset therefore never invalidates the resident `bg_vbuf`/`glyph_vbuf`, so `set_left_inset` mirrors `set_top_inset` and calls only `write_uniforms()` (no `last_snapshot = None`). The app re-fits the grid to the new `grid_size()` separately (a real content change on its side), which is where a fresh snapshot originates. Rejected: resetting `last_snapshot` in the setter (an unnecessary re-shape; contradicts the idle-CPU cache design, G1).

## Constraints
- `crates/renderer/src/lib.rs` must not import `winit` or any `app` type; the crate stays window-agnostic (dependency-direction rule).
- WGSL uniform structs must be 16-byte-aligned multiples and byte-match their Rust `#[repr(C)]` mirrors; `uniform_blocks_are_16_byte_aligned` must stay green (`lib.rs:1043-1048`).
- `top_inset` and all its existing readers (cursor layer, image layer, current tab bar, `grid_size`) must keep working unchanged.
- With `left_inset == 0.0`, rendering output and `grid_dims` results must be byte-identical to the pre-change behavior (default path unchanged).
- No `unwrap()` outside `#[cfg(test)]`; macOS/Metal target only (no cross-platform `#[cfg]`).
- `cargo build`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` all green (SD4).

## Requirements

### R0: The renderer reserves a caller-set left band (grid narrows, glyphs shift right)
Seeded from the manifest `accept-seed`.

#### R0.1: A left inset shifts the grid and reduces reported columns
- **Given**: A renderer whose grid is `C` columns wide with `left_inset == 0.0`
- **When**: The caller invokes `set_left_inset(px)` with `px` spanning `k` whole cell widths, then reads `grid_size()`
- **Then**: `grid_size()` reports `C - k` columns, `rows` are unchanged, and subsequent frames draw the grid/glyphs starting `px` physical pixels from the left edge

### R1: `grid_dims` reserves the left inset in the column count
Derives from SD1 + D6.

#### R1.1: Left inset reduces columns, not rows
- **Given**: `grid_dims(1200.0, 800.0, (10.0, 20.0), top_inset=0.0, left_inset=0.0)` yields `(120, 40)`
- **When**: The same call is made with `left_inset = 200.0`
- **Then**: It yields `(100, 40)` — cols shrink by `floor(200/10)=20`, rows stay `40`

#### R1.2: A pathological inset still yields at least one column
- **Given**: A framebuffer `1200.0` px wide with `10.0` px cells
- **When**: `grid_dims` is called with `left_inset = 10_000.0` (wider than the window)
- **Then**: `cols == 1` (the `.max(1)` floor holds, mirroring the rows floor)

#### R1.3: `grid_size()` feeds both insets into `grid_dims`
- **Given**: A renderer with `top_inset = t` and `left_inset = l`
- **When**: `grid_size()` is called
- **Then**: It returns `grid_dims(config.width, config.height, cell_size, t, l)` — both insets applied

### R2: `left_inset` state, setter/getter, and `FrameCtx` field mirror `top_inset`
Derives from D5.

#### R2.1: `set_left_inset` clamps negatives and updates uniforms
- **Given**: A renderer with `left_inset == 0.0`
- **When**: `set_left_inset(-5.0)` is called, then `left_inset()` is read
- **Then**: `left_inset()` returns `0.0` (clamped via `.max(0.0)`), and both uniform buffers have been re-written with the new value

#### R2.2: `FrameCtx` exposes `left_inset` to draw layers
- **Given**: A registered `DrawLayer` recording a frame while `left_inset == 96.0`
- **When**: The layer reads `ctx.left_inset` inside `record`
- **Then**: It observes `96.0` (the same value `set_left_inset` stored), available beside `ctx.top_inset`

### R3: Both shaders shift `px.x` by `left_inset` with matching, aligned uniforms
Derives from D7.

#### R3.1: The cell-bg shader offsets the grid horizontally
- **Given**: `cells.wgsl` with `left_inset` in its `Uniforms`
- **When**: `vs_main` computes clip space
- **Then**: `clip.x` uses `(px.x + u.left_inset) / viewport.x * 2 - 1` (the `x` twin of the existing `y`/`top_inset` shift)

#### R3.2: The glyph shader offsets glyphs horizontally
- **Given**: `glyph.wgsl` with `left_inset` in its `Uniforms`
- **When**: `vs_main` computes clip space
- **Then**: `clip.x` uses `(px.x + u.left_inset) / viewport.x * 2 - 1`

#### R3.3: Uniform blocks stay 16-byte-aligned (the automatically-verifiable guarantee)
- **Given**: The updated `BgUniforms` and `GlyphUniforms` Rust mirrors
- **When**: `uniform_blocks_are_16_byte_aligned` runs
- **Then**: `size_of::<BgUniforms>() == 32` and `size_of::<GlyphUniforms>() == 16` (the sizes the test can assert). WGSL↔Rust *field-offset* agreement is not machine-checked (see D7's known risk); it is guaranteed by hand-placing `left_inset` as the last scalar — `BgUniforms` offset 20, `GlyphUniforms` offset 12 — matching the WGSL struct field order

### R4: Zero-inset invariance (the default path is unchanged)
Derives from SD1 (additive) + the Non-goals.

#### R4.1: `left_inset == 0.0` reproduces today's geometry exactly
- **Given**: A renderer left at its default `left_inset == 0.0`
- **When**: `grid_size()` and a frame are produced
- **Then**: `cols` equal the pre-change value (`floor(width/cell.0)`) and the shader clip math reduces to the original (`+ 0.0`), i.e. output is byte-identical to before this feature
