# Spec: tab-click-switch

## Meta
- **Created**: 2026-07-19
- **Type**: dev
- **Status**: drafting
- **Set**: left-tab-sidebar (`specs/left-tab-sidebar/partition-manifest.md`)
- **Batch**: generated by decompose via specify `mode: batch`
- **Complexity**: Simple–Medium (brownfield input wiring across the THREE inset seams — `start()`, `Resized`, and `settings::apply` config-reload — plus mouse+keyboard actors; owning `settings.rs` is deliberate so the third seam is not silently missed)

## Goal
Wire the app to the new left sidebar and add click-to-switch: reserve the sidebar via `set_left_inset(tab_bar::width_px(cell_w))` (sizing the grid to it), and translate a left-mouse press inside the sidebar into a tab switch by consuming the shared `tab_bar::tab_at` hit-test → `Tabs::jump`. All existing chords (Cmd+T/W, next/prev, Cmd+1..9) keep working.

## Non-goals
- The `left_inset` renderer primitive (owned by `renderer-left-inset`).
- The vertical layout + geometry functions (owned by `vertical-tab-sidebar`; this feature *calls* `width_px`/`tab_at`).
- Grid-area mouse behavior (text selection, copy-on-select, scroll-wheel) — a click outside the sidebar is a no-op here.
- Changing the keyboard chord table or the `on_key` dispatch order (SD3).
- Drag-to-reorder, right-click menus, close-on-click affordances.

## Confirmed Goal
On startup the app reserves the left sidebar with `renderer.set_left_inset(tab_bar::width_px(cell_w))` (top inset left at `0.0`), so `grid_size()` — already used to size every session and re-fit on `Resized` — reports the narrower column count. A new pure translation `input::tab_target(cursor: (f64, f64), cell: (f32, f32), left_inset: f32, count: usize) -> Option<usize>` mirrors `input::tab_action` (raw device input → intent): it casts the winit `f64` cursor, derives the stride via `tab_bar::tab_height_px(cell.1)`, and delegates the floor/bounds geometry to `renderer::tab_bar::tab_at` (SD2). The event loop tracks the cursor via `WindowEvent::CursorMoved` and, on a left `WindowEvent::MouseInput` press, feeds the position to `tab_target`; a `Some(i)` runs the existing switch path (`Tabs::jump` + `sync_tab_model` + overlay `notify_active_changed` + `redraw`). No new switching logic; chords untouched.

## Research
- `start()` currently reserves a **top** band: `let bar_h = tab_bar::height_px(renderer.cell_size().1); renderer.set_top_inset(bar_h);` then registers the `TabBar` layer and sizes the first session from `grid_size()` (`crates/app/src/terminal_app.rs:127-154`). This becomes a **left** band via `set_left_inset(tab_bar::width_px(renderer.cell_size().0))`.
- `grid_size()` already drives session sizing at start and re-fit on resize: `WindowEvent::Resized` calls `renderer.resize(..)` → `grid_size()` → `tabs.resize_all(cols, rows)` (`terminal_app.rs:348-353`). With the left inset set, `grid_size()` returns fewer cols automatically (per `renderer-left-inset`), so no extra resize wiring is needed.
- **Third inset seam (must not be missed):** `crates/app/src/settings.rs:27` re-sets the band on every live config reload — `renderer.set_top_inset(tab_bar::height_px(renderer.cell_size().1))` — then re-fits via `grid_size()` (`settings.rs:23-32`). Reached through `UserEvent::ConfigReloaded` → `settings::apply` (`terminal_app.rs:317-327`). If left unchanged it would re-reserve a TOP band (double-reserve alongside the left sidebar) and never refresh the LEFT inset for a new cell width — so this feature owns `settings.rs` and swaps that line to `set_left_inset(tab_bar::width_px(renderer.cell_size().0))`.
- The switch path already exists and is reused verbatim: `do_tab_action` calls `self.tabs.jump(i)` / `next` / `prev`, then `sync_tab_model()`, `overlays.notify_active_changed(cwd)`, and `redraw()` (`terminal_app.rs:222-245`). `Tabs::jump(i)` bounds-checks `i < len` (`crates/app/src/tabs.rs:111-115`).
- Keyboard input flows through `WindowEvent::KeyboardInput` → `on_key`, whose order is overlays → router → `tab_action` chords → `encode_key` (`terminal_app.rs:249-287, 363-374`). Mouse events are **not** handled yet — `window_event`'s `match` has no `MouseInput`/`CursorMoved` arms (falls through `_ => {}` at `terminal_app.rs:403`).
- `input.rs` is the "input translation" module: pure functions over winit types, unit-tested without a window (`tab_action(key, mods) -> Option<TabAction>`, `encode_key`) (`crates/app/src/input.rs:1-55`). A pointer→tab translation belongs here beside `tab_action`.
- winit delivers `WindowEvent::CursorMoved { position: PhysicalPosition<f64> }` and `WindowEvent::MouseInput { state, button }`; physical-pixel positions match the renderer's px space (same space `tab_at` expects).
- `Renderer::cell_size() -> (f32, f32)` gives `(cell_w, cell_h)` for `width_px`/`tab_height_px` (`crates/renderer/src/lib.rs:447-449`).
- `ModifiersState` is already tracked in `Running.mods` via `ModifiersChanged` (`terminal_app.rs:344-346`) — available if a modifier guard on clicks is ever wanted (not needed for a plain left-click switch).
- Rules: `app` may depend on `renderer` (dependency direction allows app → renderer); macOS-only; no GUI crates; no `unwrap()` outside tests; per-crate `thiserror` errors.

## Decisions

### SD1: The reserved tab band moves from a top inset (reserves rows) to a left inset (reserves columns)
- **Status**: resolved
- **Rationale**: The sidebar is vertical on the left, so the grid must shrink in *width*, not height. A `left_inset` (physical px reserved left of the grid) mirrors the existing `top_inset` seam exactly: `grid_dims` subtracts it from usable width so `cols` shrink while `rows` stay full; the bg/glyph shaders shift `px.x` right by `left_inset` just as they shift `px.y` by `top_inset`; `FrameCtx` carries it so the tab layer reads one authoritative value. `top_inset` is kept in the renderer (additive, unremoved) but driven to `0.0` by the app once the sidebar is on the left. Rejected: repurposing/renaming `top_inset` (breaks the additive-seam precedent and the cursor/image layers that already read `top_inset`); a separate width-only code path (duplicates the proven inset arithmetic).

### SD2: Tab-strip geometry is defined ONCE in `tab_bar.rs` as pure functions; the app's click hit-test consumes the SAME functions
- **Status**: resolved
- **Rationale**: Click-to-switch must map a cursor (x, y) to a tab index using the exact geometry the layer draws with. Duplicating the layout math in the app would drift. So `tab_bar.rs` owns the geometry as pure, unit-testable free functions (extending the existing `height_px(cell_h)` precedent), named authoritatively so the consumer imports the right symbols: `width_px(cell_w) -> f32` (the sidebar width the app feeds to `set_left_inset`), `tab_height_px(cell_h) -> f32` (the per-tab slot height / stride), a shared forward `slot_y(index, tab_h) -> f32` the draw path uses to place each slot's top, and its exact inverse `tab_at(x, y, sidebar_w, tab_h, count) -> Option<usize>` the click path uses. Because slots have no top pad or inter-slot gap, `slot_y` (`index*tab_h`) and `tab_at` (`floor(y/tab_h)`) are exact inverses; a round-trip unit test pins their agreement so drawing and hit-testing cannot silently diverge. The app calls `set_left_inset(width_px(cell_w))` and, on a left-button press inside the sidebar, routes through the hit-test → `Tabs::jump(i)`; the SAME `set_left_inset(width_px(..))` wiring runs on the config-reload path so the reserved band never goes stale against the drawn sidebar. Rejected: computing tab bounds independently in the app (two sources of truth, guaranteed drift); exposing only raw slot rectangles (pushes the floor/bounds logic back into the caller, re-opening the drift this closes).

### SD3: Preserve the existing tab architecture and chords; click-to-switch is purely additive
- **Status**: resolved
- **Rationale**: The tab set (`Tabs`), the `TabAction` chord table (Cmd+T/W, Cmd+Shift+[/], Cmd+1..9), the one-way `TabModelHandle` data flow (app writes `TabBarModel`; renderer only reads), the `DrawLayer` registration seam (`add_layer`, z-order), and the enforced dependency direction `common ← term-core ← renderer ← app` all stay intact. The renderer never reaches into `crates/app`; the app never hands the renderer a live `Grid`. Click routing is a new `WindowEvent::MouseInput`/`CursorMoved` handler in the app that reuses the existing `Tabs::jump` + `sync_tab_model` + `redraw` path — no new switching logic. Rejected: adding a widget/GUI crate for hit-testing (violates the `no-gui-crates` rule — draw and hit-test on the cell grid ourselves).

### SD4: Every feature lands green under the project's fixed gates, including the insta suite
- **Status**: resolved
- **Rationale**: Each feature must leave `cargo build`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` (which includes the `term-core` insta snapshot tests) passing, with no `unwrap()` outside tests and per-crate `thiserror` error enums. The vte→grid insta snapshots construct grids at fixed sizes and are not expected to change; if any snapshot output shifts, it is reviewed and accepted via `/insta-review` rather than blindly overwritten. Renderer inset arithmetic stays a unit-testable free function (no GPU needed), matching the `grid_dims`/`height_px` test precedent. Rejected: skipping clippy/tests between features (each spec is independently verifiable and build-order-ready).

### D5: `start()` reserves the left sidebar via `width_px`; grid sizing flows through the existing `grid_size()` path
- **Status**: resolved
- **Rationale**: Replace the top-inset reservation with `renderer.set_left_inset(tab_bar::width_px(renderer.cell_size().0))` (leaving `top_inset` at its `0.0` default). Because session sizing and resize both already read `grid_size()` — which now subtracts the left inset from the column count (`renderer-left-inset`) — the first session and every resize automatically fit the narrower grid with **no new resize wiring**. The sidebar width comes from `tab_bar::width_px`, the same function the layer draws with (SD2), so the reserved band and the drawn sidebar are identical. Rejected: hardcoding a pixel width in the app (drifts from the layer); keeping a top inset too (double-reserves; the sidebar is the only tab surface now).

### D6: The event loop tracks the raw cursor and switches tabs on a left-button press inside the sidebar
- **Status**: resolved
- **Rationale**: Add a `last_cursor: (f64, f64)` field to `Running`, storing the **raw** `PhysicalPosition<f64>` from each `WindowEvent::CursorMoved` (no cast at capture time). On `WindowEvent::MouseInput { state: Pressed, button: Left }`, call the single translation `input::tab_target(last_cursor, renderer.cell_size(), renderer.left_inset(), tabs.len())` (D7) — which does the f64→f32 cast, derives `tab_h`, and hit-tests internally — and on `Some(i)` run the existing switch path (`tabs.jump(i)`, `sync_tab_model()`, `overlays.notify_active_changed(active_cwd)`, `redraw()`). `renderer.left_inset()` is read live at click time (not cached) so it always reflects the current sidebar width even after a config-reload/resize changed it. Press (not release) is used for snappy, standard tab-switch feel; a press outside the sidebar returns `None` → no-op (grid mouse behavior is a non-goal). Rejected: switching on release (extra latency, needs press/release pairing); adding a new switch routine (the `do_tab_action(Jump)` path already exists and is reused); caching `left_inset`/`tab_h` in `Running` (a live read cannot go stale).

### D7: `input::tab_target` is a genuine raw-input→intent translation (not a `tab_at` alias); geometry stays in `tab_bar` (SD2)
- **Status**: resolved
- **Rationale**: `pub fn tab_target(cursor: (f64, f64), cell: (f32, f32), left_inset: f32, count: usize) -> Option<usize>` lives in `input.rs` beside `tab_action`. It performs *real* translation the event loop would otherwise inline: it casts the winit `f64` physical position to `f32`, derives the per-tab stride `tab_h = renderer::tab_bar::tab_height_px(cell.1)`, treats `left_inset` as the sidebar width, and returns `renderer::tab_bar::tab_at(x, y, left_inset, tab_h, count)`. So its signature is deliberately **not** `tab_at`'s — it maps *raw device input + renderer metrics* → a tab intent, exactly as `tab_action` maps *raw `Key`+`Mods`* → a `TabAction`. The floor/bounds *geometry* is still sourced solely from `tab_bar` (`tab_at`, `tab_height_px`), honoring SD2; `input.rs` owns only the device-coordinate/metric plumbing. This earns the module placement (all raw-input→intent translation in one window-free, unit-testable spot) rather than being a hollow pass-through. Rejected: a `(x,y,sidebar_w,tab_h,count)` signature identical to `tab_at` (zero translation — a pointless alias; the reviewer's flagged failure mode); inlining the cast + `tab_height_px` call in the event loop (scatters input translation across `terminal_app.rs`, unlike the `tab_action` precedent); reimplementing the floor/bounds in the app (violates SD2).

### D9: `settings::apply` reserves the LEFT inset on config-reload — never re-reserves a top band
- **Status**: resolved
- **Rationale**: The live-config path (`settings::apply`, `settings.rs:27`) currently re-sets `top_inset = height_px(cell_h)` on every reload. This is the third and easily-missed inset seam (the others are `start()` and `Resized`). It is changed to `renderer.set_left_inset(tab_bar::width_px(renderer.cell_size().0))` — mirroring `start()` — so a font-size change refreshes the sidebar width to match the redrawn sidebar (SD1/SD2 "reserved band == drawn sidebar" holds), and no stale top band is ever reserved (avoiding the double-reserve D5's Rejected clause names). The existing `grid_size()` → `resize_all` re-fit two lines below then sizes the grid to the refreshed inset automatically. Rejected: leaving `settings.rs` untouched (ships a double-reserve + stale-width bug on the first config save — the exact gap the L2-review caught); refreshing the left inset from `terminal_app.rs`'s `ConfigReloaded` arm instead of inside `settings::apply` (splits one concern across two files; `apply` already owns inset+refit).

### D8: Keyboard dispatch and all chords are byte-unchanged; the mouse path is additive
- **Status**: resolved
- **Rationale**: The new `CursorMoved`/`MouseInput` arms are added to `window_event`'s `match` alongside the existing arms; `on_key`, its overlays→router→chords→`encode_key` order, and the `tab_action` table are not touched. So Cmd+T/W, Cmd+Shift+[/], and Cmd+1..9 behave exactly as before — click-to-switch is purely additive (SD3). Rejected: routing clicks through `on_key`/the seam (mouse is not a key; the seam is a keyboard abstraction).

## Constraints
- Do not modify the keyboard chord table (`input::tab_action`) or the `on_key` dispatch order — chords must stay byte-identical (SD3).
- The click hit-test must consume `renderer::tab_bar::tab_at` (via `input::tab_target`); the app must not reimplement sidebar geometry (SD2).
- The sidebar width fed to `set_left_inset` must be `tab_bar::width_px(cell_w)` — the same function the layer draws with (SD1/SD2).
- `crates/app` may depend on `renderer` but must not hand the renderer a live `Grid` (dependency direction; snapshots only).
- winit cursor positions are physical pixels; use them directly against `tab_at` (same space as the renderer).
- No `unwrap()` outside `#[cfg(test)]`; macOS-only (no cross-platform `#[cfg]`).
- `cargo build`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` all green, including the insta suite (SD4).

## Known Gaps
- A click in the grid area (outside the sidebar) is a no-op; text selection / scroll-wheel are out of scope.
- Tabs that overflow the window height cannot be clicked (they aren't drawn) — inherited from `vertical-tab-sidebar`'s first-cut no-scroll limit.
- `terminal_app.rs` is the event loop and has no unit tests; the mouse-routing logic is exercised through `input::tab_target`'s unit tests plus a manual/`/run-term` check.

## Requirements

### R0: Clicking a tab switches to it; the sidebar is reserved and all chords still work
Seeded from the manifest `accept-seed`.

#### R0.1: A left-click on a tab activates that tab
- **Given**: A running app with 3 tabs, tab 0 active, the sidebar drawn on the left
- **When**: The user left-clicks inside tab 2's slot in the sidebar
- **Then**: Tab 2 becomes active — its grid is shown, the sidebar highlight moves to slot 2, and cwd-derived overlays re-point at tab 2 (same effect as `Cmd+3`)

### R1: The app reserves the left sidebar and sizes the grid to it
Derives from D5.

#### R1.1: Startup reserves the sidebar width via `width_px`
- **Given**: A fresh window with cell width `cw`
- **When**: `start()` initializes the renderer
- **Then**: `renderer.set_left_inset(tab_bar::width_px(cw))` is called (and `top_inset` stays `0.0`), so `grid_size()` reports fewer columns than the full window width would give

#### R1.2: The first session and resizes fit the narrowed grid
- **Given**: The left inset is reserved
- **When**: The first session spawns and later the window is resized
- **Then**: Sessions are sized from `grid_size()` (cols already reduced by the inset) with no additional resize wiring — background tabs re-fit too (existing `resize_all` path)

#### R1.3: A live config reload refreshes the LEFT inset, not a top band
- **Given**: A running app with the left sidebar reserved and a config file edited to change the font size
- **When**: `UserEvent::ConfigReloaded` fires and `settings::apply` runs
- **Then**: `settings::apply` calls `renderer.set_left_inset(tab_bar::width_px(cell_w))` (NOT `set_top_inset(...)`), so the sidebar width matches the new cell metrics, no top band is reserved, and the subsequent `grid_size()` → `resize_all` re-fits the grid to the refreshed inset

### R2: A left-mouse press inside the sidebar switches tabs
Derives from D6.

#### R2.1: The raw cursor position is tracked
- **Given**: The pointer moves over the window
- **When**: `WindowEvent::CursorMoved { position }` fires
- **Then**: `Running.last_cursor` is updated to `(position.x, position.y)` as raw `f64` (the cast happens inside `tab_target`, not at capture)

#### R2.2: A press on a tab slot runs the existing switch path
- **Given**: `last_cursor` is inside tab `i`'s slot, `i < tabs.len()`
- **When**: `WindowEvent::MouseInput { state: Pressed, button: Left }` fires and `input::tab_target(last_cursor, renderer.cell_size(), renderer.left_inset(), tabs.len())` returns `Some(i)`
- **Then**: `tabs.jump(i)` runs, followed by `sync_tab_model()`, `overlays.notify_active_changed(active_cwd)`, and `redraw()` (the same sequence as `do_tab_action(Jump(i))`)

#### R2.3: A press outside the sidebar is a no-op
- **Given**: `last_cursor` is in the grid area (x ≥ sidebar width) or below the last tab slot
- **When**: a left press fires
- **Then**: `tab_target` returns `None` and no tab switch, redraw, or shell write occurs

### R3: `input::tab_target` translates raw cursor + metrics into a tab index (geometry from `tab_bar`)
Derives from D7.

#### R3.1: `tab_target` casts, derives the stride, and returns the hit-tested tab index
- **Given**: A cell of `(8.0, 20.0)` so `tab_height_px(20.0) = 30.0`, `left_inset = 160.0`, `count = 3`
- **When**: `tab_target((40.0_f64, 65.0_f64), (8.0, 20.0), 160.0, 3)` is called
- **Then**: It returns `Some(2)` — it cast the `f64` cursor, derived `tab_h = 30.0` from the cell height, and delegated to `tab_bar::tab_at(40.0, 65.0, 160.0, 30.0, 3)` for the bounds/floor (the derivation, not just the delegate, is what this asserts)

#### R3.2: `tab_target` returns `None` outside the band or with no tabs
- **Given**: A cell of `(8.0, 20.0)`, `left_inset = 160.0`
- **When**: `tab_target((200.0, 65.0), (8.0, 20.0), 160.0, 3)` (x past the band) and `tab_target((40.0, 10.0), (8.0, 20.0), 160.0, 0)` (no tabs) are called
- **Then**: Both return `None`

### R4: Keyboard chords are preserved (regression guard)
Derives from D8 + SD3.

#### R4.1: The Cmd chords still map to their actions
- **Given**: The unchanged `tab_action` table
- **When**: `Cmd+T`, `Cmd+W`, `Cmd+]`, `Cmd+[`, and `Cmd+1..9` are pressed
- **Then**: They still produce `New`, `CloseActive`, `Next`, `Prev`, and `Jump(0..8)` respectively (existing `input.rs` chord tests stay green), and none reaches the shell

#### R4.2: The keyboard dispatch order is unchanged
- **Given**: A key press
- **When**: `on_key` runs
- **Then**: It dispatches overlays → router → `tab_action` → `encode_key` exactly as before, with no mouse code inserted into that path
